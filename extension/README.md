# Aria2 Desktop Browser Extension

Chrome/Edge 扩展：把浏览器里的下载交给 Aria2 Desktop 处理。

## 安装

### 连接应用：一键配对（推荐）

装好扩展后，在弹窗中点「**一键配对 Aria2 Desktop**」→ 应用会弹出确认对话框 → 点「允许」，
访问密钥会**自动填入并保存**，无需手动复制粘贴。

> 安全说明：配对需要你在应用弹窗里明确点「允许」才会发放密钥；网页无法触发配对
> （仅限本机扩展来源）。如果应用弹出了你没有预期的配对请求，请点「拒绝」。

不想配对也可以手动填：到应用「设置 → RPC 安全设置」点「复制密钥」，粘贴到弹窗的
「访问密钥」输入框保存即可（两个入口等效，密钥相同）。

**解除配对**：点「解除配对」会清除扩展侧保存的密钥并恢复默认连接配置（随时可重新配对）。
注意它只清除扩展这一侧；如需**彻底撤销授权**（让旧密钥作废），请到应用
「设置 → RPC 安全设置」更换访问密钥——之后所有客户端都需要重新配对。

### 普通用户（推荐 .crx；Edge 需先放行非商店来源）
**Chrome**：打开 `chrome://extensions/` → 开启右上角「开发者模式」→ 把 `.crx` 文件**拖入页面** → 确认提示即可。
（Chrome 33 起禁止双击安装非商店扩展，拖拽是官方保留的开发者通道；会提示"未在 Chrome 网上应用店中列出"，属正常。）

**Edge**：Edge 默认**只信任自家商店**，需先放行非商店来源，否则拖拽/加载都会被拦：
1. 打开 `edge://extensions/` → 打开左下角「**允许来自其他应用商店的扩展**」→ 弹窗点「允许」
2. **重启 Edge**（该设置需重启才生效，不重启后续操作会失败）
3. 再开启右上角「开发者模式」，然后二选一：
   - 把 `.crx` 拖入页面（新版 Edge 可能不支持拖拽 crx，若拖了没反应用下面的方式）
   - **更稳**：下载 `.zip` → 解压 → 点「加载解压的扩展」→ 选择解压后的文件夹

> ⚠️ **安装时会提示「此扩展不是来自任何已知来源，可能是在你不知情的情况下添加的」——这是预期提示，不是出错。**
> 因为安装包由项目自签名、没有商店签名，浏览器无法核验发布者。确认继续（点「添加」/「仍然添加」）即可完成安装。

> 说明：`.crx` 与 `.zip` 都属于**旁加载**，缺点是**不会自动更新**（换版本要手动重装）。
> **Edge 加载项商店**版本已提交审核，通过后 Edge 用户可从商店一键安装并自动更新；
> Chrome 网上应用店暂不提交（旁加载是官方保留的开发者通道，长期可用）。

### 开发者（源码目录）
1. 打开 Chrome/Edge，进入 `chrome://extensions/`
2. 打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择本 `extension/` 目录
4. 工具栏出现扩展图标即安装完成

## 功能

- **弹窗内直接发送**：点扩展图标 → 粘贴下载/磁力链接 → 「发送到 Aria2」。
  弹窗会自动填入当前标签页的地址（仅 `http(s)`），因此对着直链页面点一下就能发。
- **右键菜单**：在链接、视频、音频上右键 → 「用 Aria2 Desktop 下载」。
- **拦截浏览器下载**（可选）：开启后，浏览器发起的下载会被取消并转交 Aria2；
  若转交失败，会自动重新发起浏览器下载，避免"下载凭空消失"。
- **分类下载**：发送的下载会自动归入引擎下载目录下的分类子目录。规则来源分两级：
  1. **App 在运行时**（推荐）：扩展把链接交给 App 的本地接口（`/api/add`）——
     **你在 App 里自定义的分类规则、子目录名、自定义目录全部生效**，文件名探测与重名判断也由 App 完成，
     并且套用与 App 内新建任务**一致的下载选项**（连接数、分片大小、是否自动开始）；
  2. App 未运行时：回落到扩展内置的默认规则（Video / Music / Images / Documents / Compressed / Programs）。
- **真实文件名探测**（可选开关）：链接里没有文件名时（如网盘直链 `.../file/<hash>?...`），
  向文件服务器获取响应头里的真实文件名，用于分类与命名。
  这同时修复了一个 aria2 的兼容问题：否则中文文件名会被存成乱码（如 `èµæ.rar`）。
  **注意：App 在运行时由 App 探测，无需开启此开关、也无需授予站点访问权限**；
  只有回落路径（App 未运行）才需要它。
- **连接管理**：配置 Aria2 RPC 主机、端口、密钥，并可一键测试连接。
- **状态指示**：弹窗顶部实时显示与引擎的连接状态；连得上但扩展被停用时也会明确提示。

## 与 App 的本地接口（推荐工作方式）

App 在运行时会在**本机回环地址**上提供一个小接口，扩展优先通过它工作——这样**分类规则以 App 为准**，
扩展不必再维护第二份规则：

| 端点 | 用途 |
| --- | --- |
| `GET /api/status` | 引擎是否运行及其版本（弹窗状态用，能区分"引擎未启动"与"接口不可达"） |
| `POST /api/add` | 由 App 事务化建任务：解析目录 → 重名改名 → 套用与 App 内新建**一致的下载选项** |
| `POST /api/resolve` | 只查询"会存到哪、叫什么"，不建任务（供界面预览等用途） |

**地址与鉴权**：`http://127.0.0.1:6801`，请求头需带 `Authorization: Bearer <RPC 密钥>`
（即 App「设置 → RPC 安全设置」中的密钥，扩展弹窗里填的也是同一个）。

**安全边界**（接口只在本机可用）：
- 只监听 `127.0.0.1`，不对局域网开放；
- 未配置 RPC 密钥时接口整体不启用；
- 拒绝 http(s) 网页来源，且响应**不带 CORS 头**——网页即便知道地址也读不到内容；
- 接口只接受下载链接（http / https / ftp / sftp / magnet），**不接受任何 aria2 选项**，
  因此无法被用来向任意目录写文件或执行命令。

App 未运行时，扩展自动回落到内置规则 + 直连 aria2，功能不受影响（只是看不到你自定义的分类规则）。

## 配置说明

点扩展图标打开弹窗：

| 项 | 说明 |
| --- | --- |
| 主机 / 端口 | 默认 `localhost:6800`。连接非本机地址时，扩展会**按需**申请该地址的访问权限 |
| 密钥 | 可选项。应用首次启动会自动生成密钥，可在 Aria2 Desktop 的「设置 → RPC 安全设置」中查看 |
| 启用扩展 | 关闭后右键菜单与拦截都不生效（弹窗内仍可看到连接状态） |
| 拦截所有下载 | 见上文「拦截浏览器下载」 |
| 探测真实文件名 | 见上文「真实文件名探测」；开启时会弹出站点访问权限申请，关闭时自动收回 |

## 权限说明（为什么需要这些权限）

| 权限 | 用途 |
| --- | --- |
| `downloads` | 拦截/取消浏览器下载，并在转交失败时重新发起 |
| `contextMenus` | 提供右键菜单项 |
| `storage` | 保存连接配置 |
| `activeTab` | 打开弹窗时读取当前标签页地址，用于自动填入 |
| `notifications` | 发送"已发送/已拦截"等结果通知 |
| `host_permissions`（本机） | 访问 `localhost` / `127.0.0.1` 上的 RPC |
| `optional_host_permissions`（可选） | 仅当你把主机改成非本机地址时，才申请该地址的权限 |

扩展不注入任何页面脚本、不读取网页内容，也不会把数据发送到 Aria2 Desktop 之外的任何地方。

## 依赖

- Aria2 Desktop 需要处于运行状态，且下载引擎已启动
- 默认 RPC 端点：`http://localhost:6800/jsonrpc`
